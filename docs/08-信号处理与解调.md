# 信号处理：频谱、检测、识别、解调

> 本文说明 `my::dsp` 做了什么、**做到哪一步**、以及为什么选 pocketfft 而不是
> liquid-dsp / FFTW / kissfft。
>
> 一句话：这是一条"拿到一段采样 → 看清里面有什么 → 认出来是什么 → 把信息解出来"
> 的最小可用链路，全部用合成信号逐条验证过（`tests/test_dsp.cpp`，33 个用例）。
> 它不是 GNU Radio，也别指望它直接解 OFDM。

---

## 1. 边界：能做什么、不能做什么

| 能力 | 状态 | 说明 |
|---|---|---|
| 频谱 / PSD | ✅ | Welch 平均周期图、窗函数、单边 dBFS 幅度谱、噪声底/SNR 估计、找峰 |
| 滤波 | ✅ | 窗函数法 FIR（低/高/带通）、RBJ 双二阶（低/高/带/陷波）、混频、整数抽取 |
| 突发检测 | ✅ | 滑窗 RMS + 10% 分位数噪声底 + 门限 + 边界细化（±8 样本） |
| 调制识别 | ✅ 规则分类器 | CW / AM / ASK / FM / FSK / PSK / 噪声，输出特征 + 置信度 |
| 模拟解调 | ✅ | AM（包络）、FM（鉴频） |
| 数字解调 | ✅ | ASK/OOK、2-FSK、BPSK（含载波频偏估计与符号定时） |
| QAM / OFDM / 扩频 | ❌ | 需要信道估计/均衡/同步子系统，见 §8 的升级路径 |
| 多信号分离 / 盲源分离 | ❌ | 不在 v1 范围 |
| 流式（分块）处理 | ❌ | 目前是批处理 API；板端按帧调用，帧间状态要自己接（见 §7） |

## 2. 为什么是 pocketfft

FFT 是整个链路的底座，自己做不了（要处理任意长度、实数优化、精度）。

| 候选 | 结论 | 理由 |
|---|---|---|
| **pocketfft**（BSD-3，单头文件） | ✅ 采用 | NumPy/SciPy 用的就是它；任意长度；单头、零构建依赖、无异常（有 `POCKETFFT_NO_EXCEPTIONS` 开关）；性能接近 FFTW |
| FFTW | ❌ | GPL（本项目要静态分发到板子） |
| kissfft | ❌ | 只支持 2 的幂，精度和速度都差一档 |
| CMSIS-DSP | ❌ | 面向 Cortex-M，A9 的 NEON 收益有限，且要拉一堆依赖 |
| liquid-dsp | ⏸ 暂不引入 | 见 §2.1 |

### 2.1 为什么暂不引 liquid-dsp

`liquid-dsp` 是"检测/识别/解调"这个领域最顺手的库（MIT，纯 C，有 modem/
symsync/agc/framing/fec）。但：

1. **没有 CMake**，只有 autotools；本工程的依赖约定是"resources/*.zip + CMake 挂载"，
   对 Windows 侧（MinGW 编、MSVC 不编）不友好；
2. 905 个 `.c` 文件、5.5 MB 源码，交叉编译和版本固定都比现在的单头文件库重得多；
3. 它用 C99 `complex.h`，**MSVC 编不了** —— 也就是说 Windows 主开发环境里
   这个组件会是"残废"的。

所以 v1 的取舍是：**FFT 用现成的（pocketfft），解调这一层自己写**。
AM/FM/ASK/FSK/BPSK 的公式是固定的、对错可以逐条测；真正容易写错的是
**同步（载波/定时）和均衡**，那部分 v1 只做了 BPSK 的平方环 + 定时搜索，
其余明确标成未实现（§8）。

> 如果你后面要 QAM/OFDM/信道编码，正确做法是把 liquid-dsp 交叉编译成
> `third_party/liquid-dsp-<ver>/{include,lib}`，在 `Deps.cmake` 里按 ncnn 的
> 套路挂一个可选后端，然后只把 `modem`/`firfilt`/`symsync` 包进来。
> 现成的构建脚本可以参考 `scripts/build-ort-armv7-petalinux2020.sh` 的结构。

## 3. API 总览

```cpp
#include <my_cpp_libs/dsp/dsp.hpp>
```

| 分组 | 接口 | 说明 |
|---|---|---|
| 变换 | `make_window` / `fft` / `ifft` | ifft 不带 1/N 缩放 |
| 频谱 | `welch` → `Spectrum` | dBFS 幅度谱（满幅正弦 = 0 dB）、噪声底、峰 |
| 找峰 | `find_peaks` / `estimate_snr_db` | 局部极大 + **真·prominence** + 高出噪声底粗筛；语义见 §10 |
| 滤波 | `fir_lowpass/highpass/bandpass` + `fir_apply` | 线性相位、群延迟补偿 |
| IIR | `biquad_design` / `biquad_apply` | RBJ 双二阶，转置直接 II 型 |
| 混频 | `mix_down`（实/复两个重载） | 实信号版本会留 -2f 镜像，干净搬移用复信号 |
| 抽取 | `decimate` | 自带抗混叠 FIR |
| 检测 | `detect_bursts` | 返回 `{begin, end, peak_db}`，边界已细化 |
| 分析 | `analyze` → `Features` | 包络/瞬时频率/谱形状共 10 个特征 |
| 识别 | `classify` → `Classification` | 规则分类器 + 置信度 |
| 解调 | `demod_am/fm/ask/fsk/bpsk` | 见 §5 |

## 4. 调制识别的判决树

`classify()` 是**可解释的规则树**，不是机器学习模型。理由：板端要能回答
"为什么判成 FSK"，而且训练数据你也没有。

`analyze()` 在合成信号上实测的特征（fs=2k~8k，SNR 30~40 dB）：

| 信号 | envelope_cv | envelope_low_frac | inst_freq_std | two_level | quiet | flatness | 判定 |
|---|---|---|---|---|---|---|---|
| CW | 0.007 | 0.00 | 0.002 | 0.39 | 0.20 | 0.00 | CW ✓ |
| AM (m=0.8) | 0.566 | 0.26 | 0.005 | 0.78 | 0.39 | 0.00 | AM ✓ |
| ASK (OOK 50%) | 0.675 | 0.33 | 0.575 | 0.79 | 0.03 | 0.04 | ASK ✓ |
| FM (β=2) | 0.007 | 0.00 | 0.110 | 0.33 | 0.10 | 0.00 | FM ✓ |
| FSK (h=0.25) | 0.008 | 0.00 | 0.074 | **0.84** | 0.03 | 0.00 | FSK ✓ |
| 白噪声 | — | — | — | — | — | >0.5 | 噪声 ✓ |

判决顺序（每一步的阈值都写在 `classify()` 里，可调）：

```
SNR < 6 dB 或 flatness > 0.55            -> 噪声
envelope_cv < 0.15 且 inst_freq_std<0.02 -> CW
envelope_cv >= 0.30                      -> low_frac>=0.30 ? ASK : AM
two_level >= 0.60                        -> FSK
quiet >= 0.50                            -> PSK
inst_freq_std >= 0.02                    -> FM
否则                                       -> Unknown
```

几个设计点：

- **瞬时频率先做 5 点平滑再统计**。相位求导会把白噪声放大几十倍，
  不平滑的话 40 dB SNR 的纯 CW 也会被算成"有频率调制"。
- **"quiet" 用 std 做尺度，不用 max**。瞬时频率是重尾分布，max 会被噪声尖峰
  支配，PSK（多数时间相位不变 + 瞬间跳变）和 FM（连续调制）就分不开。
- **AM 和 ASK 靠 `envelope_low_frac` 分**：AM 的包络是正弦（很少停在谷底），
  OOK 的包络有一半时间在 0。

## 5. 解调实现要点

| 调制 | 做法 | 已知限制 |
|---|---|---|
| AM | 解析信号包络 → 去直流 → 二阶低通 | 过调制（m>1）会失真；需要载波附近的带通时自己做 |
| FM | 解析信号相位差分（鉴频）→ 去直流 → 低通，输出单位 Hz | 带宽超过奈奎斯特会混叠；没有去加重 |
| ASK | 包络 → 4 个定时候选里挑"符号间方差最大" → 门限判决 | 门限默认 (max+min)/2，突发内幅度起伏大时要用给定值 |
| 2-FSK | **绝对**瞬时频率（不去均值）→ 定时搜索 → 就近判决 | 只支持 2-FSK；多电平要扩展成 M 个参考频率 |
| BPSK | 平方环估频偏 → 试两个频偏符号 → 相干度×功率挑定时 → 去公共相位 → 判决 | 只做 BPSK；有 π 相位模糊（要前导码/差分编码定相） |

### BPSK 为什么多了两步

1. **平方环只能给 |频偏|**：x² 的谱峰在 2|Δf|，符号信息丢了。所以两个符号
   各试一遍，用"符号平方后的相干度" |Σs²|/Σ|s|² 挑对的那个。
2. **相干度挑不了定时**：BPSK 的符号只要落在实轴上（哪怕一半取自相邻符号），
   相干度都是 1。所以定时另用"平均符号功率"挑——对齐时每个符号窗刚好覆盖
   一个符号，功率最大。

这两条都是实现时踩出来的：只靠相干度会让输出**整体错一个符号**，
BER 固定在 0.5 左右（`tests/test_dsp.cpp` 里那条带 3 Hz 频偏的用例就是守它的）。

### 突发检测的边界细化

`detect_bursts` 先按窗口算 RMS，粗边界最多会早/晚一个窗口。返回前会用
16 点滑窗幅度往里收，收到"超过突发峰值 10%"为止（±8 样本）。不细化的话，
下游解调拿到的段会带一截静音，符号定时被带偏——`examples/08` 里
FSK 的 BER 会从 0 变成 0.35。

## 6. 实测（x64，**不是板端数据**）

MinGW GCC 15.2 / `-O3` / 单线程（`build/dsp_bench.cpp`，未入库）：

| 操作 | 规模 | 耗时 |
|---|---|---|
| `welch` | 120k 样本，nfft=1024，50% 重叠 | 2.97 ms |
| `analyze` | 8192 样本 | 1.28 ms |
| `detect_bursts` | 120k 样本，窗 128 | 1.31 ms |
| `demod_bpsk` | 1600 样本（80 符号） | 0.34 ms |

板端参考：A9 @666MHz 是标量 + 单精度 FPU，上面这些数大概要乘 15~25 倍。
也就是说 8 kHz 采样的**每帧 4096 点**做一次 `analyze`，板端大约 20~30 ms ——
对"每秒看几次"的监视类应用够用，对连续 100 kHz 实时流不够（那要把
`analyze` 里的解析信号 FFT 降到 1024 点、并只对突发段做）。

## 7. 板端注意事项

> **板端实测（2026-11-16，Zynq-7020 / Cortex-A9 @666MHz）**：`dsp` 套件 27/27 通过（<1 s）；
> `example_signal` 全链路（4 个突发：识别 CW/AM/FM/FSK 全对，FSK BER = 0.000）**67 ms**。
> 48 kHz 采样、毫秒级突发的实时处理在 A9 上有充足余量。

1. **单精度就够，但别用 double 重写**：Cortex-A9 的 VFP 是双精度硬件，但
   内存带宽是瓶颈；信号已经是 float，无需转换。
2. **`analyze()` 会分配几次临时缓冲**（解析信号、相位、频谱），
   每帧几 KB 到几十 KB。板端跑之前先确认堆够用；要零分配就得把
   `detail::analytic` 改成外部缓冲，属于后续优化。
3. **采样率必须显式传**：所有频率参数都是 Hz，库不做全局状态。
4. **`decimate` 的 FIR 是 O(N·M)**：factor=10 时 M=161，10 万点要 1600 万次乘加。
   板端建议分帧做，或后续换成多相实现。
5. **无异常**：pocketfft 在 Deps 里定义了 `POCKETFFT_NO_EXCEPTIONS`，
   DSP 组件可以进 `-DMYLIB_NO_EXCEPTIONS=ON` 的子集（core + math + dsp + net）。

## 9. 流式（分块）处理

板端的信号不是一个完整数组，而是"每帧到达一块"。批处理 API 一次吃一整段，
帧与帧之间需要调用方自己接的状态有五样：**FIR 延迟线、IIR 状态、NCO 相位、
抽取相位、AGC 增益**。这五样正好是流式 DSP 最容易写错的地方，所以单独封成对象。

```cpp
#include <my_cpp_libs/dsp/stream.hpp>

// FIR：跨块连续，process()+flush() 与整段 fir_apply() 逐点一致
my::dsp::FirFilter fir(lowpass);
for (each block) {
    auto y = fir.process(block);     // 只给"抽头窗口已完整"的部分
    consume(y.value());
}
consume(fir.flush().value());        // 补出尾部 delay() 个，并复位

// NCO + 混频：相位累加器跨块连续（每块从 0 开始 = 周期性相位跳变，最常见的错）
auto mixer = my::dsp::ComplexMixer::create(if_hz, fs);
auto baseband = mixer.value()->process(block);   // 实/复输入都有重载

// 抽取：与批量 decimate() 同款抗混叠 FIR
auto dec = my::dsp::Decimator::create(/*factor=*/10, fs);

// AGC：逐样本 RMS + attack/release，增益跨块保持
my::dsp::AgcOptions opt;
opt.target_rms = 0.2; opt.attack = 0.01; opt.release = 0.2; opt.sample_rate = fs;
my::dsp::Agc agc(opt);
agc.process_inplace(block);
```

### 9.1 边界语义（与批量版对齐的地方）

| 类 | `process()` 输出 | `flush()` |
|---|---|---|
| `FirFilter` | 抽头窗口已完整的样本，相对输入滞后 `delay()` | 零延拓补出尾部 `delay()` 个，然后复位 |
| `Decimator` | 只输出"新增的完整符号"，比批量结果晚约 8 个符号 | 零延拓补尾并复位 |
| `ComplexMixer` | 与输入等长，相位连续 | —（无内部缓冲）|
| `BiquadFilter` | 与输入等长 | —（无内部缓冲）|
| `Agc` | 就地改，与输入等长 | —（增益就是状态）|

**`process()` 逐块 + 一次 `flush()` 的结果，与批量 API 整段处理逐点一致** ——
这条不是靠"看着对"，而是测试里用同一段信号分别走两条路逐点 `CHECK_NEAR` 钉住的
（`tests/test_dsp_stream.cpp`，10 个用例）。

### 9.2 为什么必须"跨块延续相位/延迟线"

用 `mix_down()` 一帧一帧地喂，每帧相位都从 0 开始，等价于给信号乘了一个每帧重置的
复指数 —— 频谱上出现**帧率处的杂散**，混频后再滤波也去不掉。同理，FIR 每帧从零延迟线
开始会在帧边界产生"台阶"。这两个错误在单帧上看不出来，只有在连续流上才能发现，
所以流式 API 的价值主要在于**把这类错误变成写不出来**。

### 9.3 已知限制

- 每个 `process()` 会分配一块缓冲（`combined`/输出）。板端若要求**零分配**，
  需要改成"调用方提供输出缓冲"的形态（`process_into(in, out)`）——留作后续；
- 只有单通道：多通道需要每通道一个实例（这样也更省心，不用做 2D 索引换算）；
- 频谱类仍然是批量的：`welch()`/`analyze()` 用的是整段 FFT，流式谱估计要另做
  （滑窗 + 累积），目前没有需求就没有做。

## 10. 峰值检测的语义（0.1.4 定稿）

### 10.1 旧实现错在哪

`find_peaks(s, min_prominence_db=6)` 原来的判据是"局部极大 **且** 高于
`noise_floor_db + 6 dB`"。在"1 kHz 单音 + 平坦噪声底"的谱上实测：

```
返回 8 个峰（max_peaks 默认值），其中 7 个在 -133 ~ -139 dBFS：
  bin=41  320.3 Hz  -139.2 dB
  bin=48  375.0 Hz  -137.2 dB
  bin=128 1000.0 Hz     0.0 dB   <- 真正的峰，排在第 4 个
  ...
peaks.front() -> 320.3 Hz        <- 用户拿到的是错的答案
```

原因：`noise_floor_db` 是全谱**中位数**，而单音谱里 512 个 bin 有 511 个都在
-140 dB 附近，中位数≈-145 dB；"高 6 dB"于是把噪声起伏（幅度 4~6 dB）也放进来了。

### 10.2 现在的判据

三个条件**同时**满足才算峰：

1. 局部极大（左邻更小、右邻不大于它）；
2. `db[k] >= noise_floor_db + min_prominence_db` —— 便宜的粗筛；
3. **真·prominence ≥ `min_prominence_db`**：

```
prominence = db[k] - max(left_valley, right_valley)
left_valley  = 从 k 往左走，直到遇到比它更高的 bin（或边界）这一路的最小值
right_valley = 同上往右
```

这是地形学与光谱学共用的**标准定义**（scipy 的 `prominence` 也是它）。
噪声起伏的 prominence 只有 1~2 dB，天然过不了 6 dB；而一个真峰无论坐在多高的
"地台"上，只要比两侧谷底高 6 dB 就会留下。

### 10.3 输出顺序与截断

- **按频率升序**（和 `scipy.signal.find_peaks` 按 index 升序一致）；
  想要"最强的峰"用 `Spectrum::peak_bin/peak_freq/peak_db`；
- `max_peaks` 截断保留**最强的**几个（内部先按 dB 排序再截断），不是频率最低的；
- `Peak` 新增 `prominence_db` 字段，方便调用方按自己的门限二次过滤。

### 10.4 已知限制（用测试钉住了）

这两个坑不是 bug，是这类判据的性质；`tests/test_dsp.cpp` 里各有一条用例。

| 场景 | 现象 | 应对 |
|---|---|---|
| **Welch 平均段数很少**（例如 8192 点 / nfft=4096 = 3 段） | 单个噪声 bin 本来就能比中位数高 6 dB 以上，默认门限会放进几个噪声峰 | 调高 `min_prominence_db`（12 dB 即可挡住），或按 `Peak::db` 再过滤 |
| **完全没有噪声的合成谱** | FFT 舍入误差形成 -150~-160 dB 的起伏，它们相对"更深"的谷底有 20~30 dB 的 prominence，会被当成峰 | 仿真时给信号加一点噪声（真实系统总有）；或把绝对门限提到 -120 dB 以上 |

真正抗噪的检测器要 **CFAR**（`ca_cfar` / `os_cfar`）——仍列在 §8 的待办里。

### 10.5 实测（x64，fs=8 kHz，nfft=1024，Hann）

| 信号 | 0.1.3 及以前 | 0.1.4 |
|---|---|---|
| 1 kHz 单音 | 8 个峰（7 个假峰，front=320 Hz） | **1 个峰**（bin 128，prominence 150 dB） |
